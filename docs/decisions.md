## W10. タグの絞り込みは URL に持ち、server に任せる

- 決めた人：AI（タグの形と絞り込みの意味は親の D49）　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- 選んだタグは URL の `?tag=…` に持つ。REST の一覧と同じ書き方で、開き直しても、URL を人に渡しても同じ一覧になる。テストケースの画面や実行の結果に移っても、後ろに付けたまま残す。
- 絞り込みは web でせず、server の REST の `tag` に渡す。契約の一致の決まり（文字の完全な一致・全部持つもの）を二か所に書かないため。読んだ一覧は、タグの組ごとに別の入れ物に持つ（`queryKeys.testcaseList`）。承認や消すときは、絞り込んだものも含めて、読んだ一覧を全部直す。
- 選べるタグは、いま一覧に出ているものが持つタグにした。タグを選び直して読み終えるまでは、前の一覧とタグを出したままにする（`keepPreviousData`）。続けて押したいタグが、読み込みの間に消えないように。空の `?tag=` は選んでいないものとして扱う（契約のタグは 1 文字以上）。全部持つものに絞るので、選ぶほど候補が狭まり、選んでも何も出なくなるタグは出ない。全部のタグを別に読むことはしない（server にタグの一覧の道がなく、いまは要らない）。選んだタグは、一覧になくても外せるように出しておく。
- タグはバッジ（`outline`）で、一覧と詳細の両方に出す。タグのないものは何も出さない。
- デモ版（Vercel）には、契約の例のほかに、題とタグだけを変えたものを 3 件、最初から並べる（人の頼み、2026-11-17）。例が一件だけでは、絞り込んでも何も変わらないため。`data/` は契約の例と同じに保つ決まりなので、ファイルは足さず、`src/demo/index.tsx` で例から作る。手順とスクショは例と同じなので、題もそれに合うものにした。確認は要らないものにした（確認待ちは、デモの「登録する」で出るものだけにしておく）。

## W9. 進行中の操作は、TanStack Query の入れ物から読む

- 決めた人：AI　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- テストケースの画面の操作（承認・実行・消す）に、テストケースごとの名前（`mutationKey`）を付けた。押せるかどうかは、画面の中の状態ではなく、入れ物（MutationCache）にある進行中の操作から読む（`useMutationState`）。画面を離れても操作は入れ物に残るので、戻ったときも押せないままになり、終わると結果が出る。
- 失敗も同じく入れ物から読み、そのテストケースのいちばん新しい操作が失敗していたら出す。離れている間に失敗しても、戻ったときに出るように（別の AI のレビューで見つかった）。新しく操作を始めると消える。
- 実行が終わって結果を足すとき、読み直しで同じものが先に届いていたら、二つ並べない。
- 実行中かどうかを持つ場所を別に作らず（React の Context や、自前の入れ物など）、TanStack Query が持っているものを使った。新しい置き場所が要らないため。
- 承認と消すも同じ扱いにした。同じ操作の中にあり、分ける理由がないため。ほかのテストケースは、実行中でも操作できる（server が重なった実行を断る、親の「runner_busy」）。
- 実行が終わって結果を足す前に、そのテストケースの実行の一覧の読み直しを止める。戻ったときに始まった読み直しの古い応答で、足した結果が消えないように。

## W8. 見た目を Tailwind CSS と shadcn/ui に移す

- 決めた人：AI（使う道具は親の D43）　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- Tailwind CSS 4（`@tailwindcss/vite`）と shadcn/ui（CLI 4.23、`radix-nova`、色は `neutral`）を入れた。部品は shadcn の CLI で `src/components/ui/` に置き、手元のソースとして直してよいものにした。いま使うものだけを足した（ボタン・バッジ・カード・アラート・ダイアログ・確かめのダイアログ・チェックボックス）。
- 手書きの `styles.css` はなくし、`src/index.css` には Tailwind と shadcn の読み込みと、色などの値だけを置く。クラスを手で書かない。
- 色は、shadcn の既定（白黒の `neutral`）ではなく、前の手書きの CSS と同じ値を shadcn の色の名前に当てた（主の色は青、成功は緑、失敗は赤、確認待ちは黄。暗い色も前と同じ）。人のレビューで、前の色に戻すことにした（2026-11-17）。shadcn の既定にない、成功の `success`・確認待ちの `warning` と、それぞれの淡い背景（`*-muted`）を足し、バッジの色にした。状態から色への対応は `labels.ts` に置く。
- フォントは、shadcn の既定の Geist ではなく、前と同じ日本語の入ったもの（Segoe UI・Yu Gothic UI・Meiryo）にした。Geist には日本語の字がない。
- 暗い色は、shadcn の既定（`.dark` のクラス）ではなく、前と同じく OS の設定に従う（`prefers-color-scheme`）。切り替えのボタンはまだ要らない。
- 消すときの確かめは、ブラウザの `window.confirm` から、shadcn の確かめのダイアログ（AlertDialog）にした。見た目をそろえるため。スクショの拡大は Dialog にし、前と同じく、画面いっぱいの黒の半透明の上に画像だけを出す（どこを押しても、Esc でも、右上の「閉じる」でも閉じる）。そのため、Dialog の部品に後ろの幕の見た目を変える口（`overlayClassName`）を足した。
- 部品は、shadcn の CLI の既定どおり `cn` のパッケージ（shadcn が出している、clsx と tailwind-merge の代わり）を使う。
- 外枠（上の帯・左の一覧）は、shadcn の Sidebar の部品ではなく、Tailwind で書いた。いまは一覧が一つだけで、Sidebar の部品（開け閉め・幅の記憶など）が要らないため。
- e2e は、クラス名ではなく、役割（`getByRole`）と shadcn の `data-slot` で探す形にした。見た目を変えても落ちないように。
- Tailwind・shadcn の CLI・`tw-animate-css` は、ビルドのときに CSS を作るのにだけ使うので、`devDependencies` に置いた。

## W7. 画面を URL で分け、読み込みを TanStack Query に任せる

- 決めた人：AI（使う道具は親の D43）　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- React Router 8 と TanStack Query 5 を入れた。React Router は宣言の形（`<Routes>`）にした。データの読み込みは TanStack Query が持つので、router の loader は使わない。router は外から渡す（本物とデモ版は `BrowserRouter`、テストは `MemoryRouter`）。
- URL は三つ：一覧 `/`、テストケース一つ `/testcases/{id}`、実行の結果一つ `/testcases/{id}/runs/{run_id}`。実行の結果はテストケースの画面の中で選ぶものなので、その下に置いた。一覧は左にいつも出す。
- 一覧とタブは、ボタンから `a`（リンク）に変えた。URL を変えるものなので。見た目はボタンのまま（`link-button`）。
- テストケース一つは、契約の `GET /testcases/{id}` で読む。一覧にあればそれを先に出す（ちらつかないように）。あとで一覧を絞り込んでも、URL で開いた画面が消えないため。偽の server にもこの道を足した。開いている間は一覧と同じ間隔で読み直す（前は一覧から取っていたので、承認などが出ていた）。
- 実行の結果一つは、そのテストケースの実行の一覧から選ぶ。`GET /runs/{id}` は使わない。一覧に全部あり、二重に読まずに済むため。
- 前と同じく、失敗しても自動では読み直さない（`retry: false`）。画面が見えていないときは一覧を読み直さないのは、TanStack Query の既定のまま。
- テストケース一つの読み直しが失敗したら、前に読んだものがあってもエラーを出す。ほかで消されたものが、承認・実行できるまま残らないように（TanStack Query は、読み直しに失敗しても前のデータを持つ）。一時的に server に届かないときも詳細は隠れるが、次の読み直しで戻る。
- 承認・実行・削除のあとは、読み直さずに入れ物を直す（前と同じ見え方）。直す前に途中の読み直しを止める（あとから届いた古い応答で上書きされないように）。消したら、そのテストケースと実行の一覧の入れ物も捨てる（「戻る」で消したものが一瞬出ないように）。実行したら、その結果の URL に移る。画面の移動は、その画面にいるうちに終わったときだけにした。実行中にほかのテストケースへ移ったのに、終わったときに引き戻されないように。
- Vercel のデモ版は、どの URL でも `index.html` を返すようにした（`vercel.json` の `rewrites`）。URL を直接開けるように。デモ版のデータはブラウザの中だけなので、登録したものの URL は再読み込みで見つからなくなる。

## W4. デモ版（Vercel）は、ブラウザの中の偽の server で動かす

- 決めた人：AI　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- 形は親の D30。`npm run build:demo`（`vite build --mode demo`）でデモ版を作り、`main.tsx` が本物の `/api` の代わりに `src/demo/` を読み込む。普通のビルドにはデモ版のものが入らない（動的な import）。Vercel は `vercel.json` で `build:demo` を使う。タスクの `VITE_DEMO=1` の代わりに mode にしたのは、Windows でも環境変数の書き方を気にせずに済むため。
- 偽の server は一つ（`src/demo/fakeServer.ts`）にし、契約の判定を外から渡す形にした。テスト（`tests/fakeServer.ts`）は親の JSON Schema の判定を渡し、デモ版は渡さない（ブラウザに ajv と親の契約を持ち込まないため）。二つに分けると動きがずれるので、動きは共通にした。
- 登録（`POST /testcases`）を偽の server に足した。デモ版には AI がいないので、「AI に頼んだことにして、登録する」のボタンで契約の例（`testcase.add.json`）を登録する。本物の server の関門（形式と部品の辞書）は持たない。
- データは親の契約の例を `src/demo/data/` に写す（Vercel には隣の `../qata/` がない）。写したものが親の例と一字一句同じことをテストで確かめる。prettier にかけない（書式で変わらないように）。
- スクショは、この PC の本物の電卓（Windows 11）を、契約の例の手順のとおりに一度だけ撮ったもの（`src/demo/screenshots/`）。runner が本物になったら、その出力で撮り直してよい。実行の例の `screenshot_id` がすべて PNG で揃っていることをテストで確かめる。
- デモ版であること・再読み込みで戻ること・本物では AI に日本語で頼むことを、画面の上の帯に出す。一覧の読み直しは 1 秒ごと（メモリの中なので軽い）。

## W2. 画面と、server への中継

- 決めた人：AI　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- 画面は一枚。左にテストケースの一覧（新しい順、確認の状態の印つき）、右に選んだものの詳細。詳細には、元の日本語（`instruction`）と生成されたステップを横に並べ、その下に承認・実行のボタンと、実行の結果を置く。
- ステップは「「1」のキーを押す」のように、人が読む一文にして出す。確認事項（`expect_text`）は太字にし、結果では期待と実際の値を並べる。
- 確認待ち（`pending`）のものは「実行する」を押せなくし、「承認する」を出す。server も 409 ではじくが、押す前に分かるようにする。
- `needs_review` は登録のときに AI が決める（契約に変える道がない）ので、web ではチェックボックスを読むだけで出す。
- 実行の結果は、そのテストケースの実行を新しい順に並べ、選んだものを出す。各ステップにスクショの縮小を付け、押すと大きく出す。
- 一覧は 3 秒ごとに読み直す（画面が見えているときだけ）。AI が MCP で登録したものが、開いたままの画面に出るように。デモのため。
- web は `/api` を vite の中継で server に送る。server に CORS の設定を足さずに済み、web からは同じ場所に見える。本番のための配信（`vite build` の置き場所）は、要るときに決める。
- 消す（`DELETE /testcases/{id}`）も付けた。デモで登録し直すときに要るため。押す前に確かめる。
